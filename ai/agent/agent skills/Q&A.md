# agent skills 概念，应用场景 解决的问题 与mcp的差异



在 AI 智能体（AI Agents）的演化过程中，**Agent Skills（智能体技能）** 和 **MCP（Model Context Protocol，模型上下文协议）** 是目前最前沿的两个核心概念。它们分别解决了“怎么做”和“用什么做”的问题。

***

## 1. Agent Skills 的概念

**Agent Skills** 是对“程序性知识”的标准化封装。如果把 AI 智能体比作一个员工，那么：

- **基础模型** 是他的“大脑”（通用推理能力）。
- **Agent Skills** 就是他的“专业操作手册”或“SOP（标准作业程序）”。

它通常以文件夹的形式存在，包含 **Markdown 指南、脚本代码、模板和元数据**。它告诉 AI 在面对特定场景时，应该分几步走、调用哪些工具、遵循什么规范。

### 解决的核心问题

- **上下文爆炸：** 传统的 Tool Use 需要把所有工具详情都塞进 Prompt，导致 Token 消耗巨大。Skills 采用“按需加载”，只有匹配到场景时才读取具体逻辑。
- **能力鸿沟：** AI 有了工具（比如 SQL 接口）不代表它能写出高效安全的 SQL。Skills 提供了“领域知识”，弥补了 AI 在特定专业流程上的经验不足。
- **可复用性：** 开发者可以将一套复杂的业务逻辑封装成 Skill，在不同的 Agent 之间自由迁移。

### 应用场景

- **复杂文档处理：** 比如“PDF 编辑技能”，包含如何提取表格、如何保持格式、如何合并页面的具体指令。
- **专业代码审查：** 封装特定公司的代码规范（Linting 规则、安全检查项），让 Agent 按标准执行。
- **垂直行业流转：** 如“财务报表审计技能”，规定必须先对账、再核实税率、最后生成分析图表。

## 2. Agent Skills vs. MCP 的差异

这两个概念经常被一起提及，但它们处于不同的架构层级：

| **维度**     | **MCP (Model Context Protocol)**                        | **Agent Skills (智能体技能)**                        |
| ------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| **定位**     | **连接层协议**（基础设施）                              | **逻辑层封装**（操作规范）                           |
| **比喻**     | 像 **USB 接口** 或驱动程序                              | 像 **专业技能证书** 或员工手册                       |
| **核心职责** | 解决“**连接**”：让模型能访问外部数据库、文件系统、API。 | 解决“**执行**”：教模型如何正确、专业地使用这些连接。 |
| **内容**     | 定义了客户端与服务器通信的标准格式。                    | 包含 Markdown 说明、Helper 脚本、最佳实践。          |
| **运行位置** | 通常是远程服务器或本地服务进程。                        | 通常作为本地文件包，直接读入模型的推理循环。         |
| **协作关系** | **MCP 提供“手”**，让 AI 够得着工具。                    | **Skills 提供“脑”**，指导这只手怎么动。              |

## 3. 协同工作示例

想象你要让 AI 帮你分析一份公司内部数据库的销售数据：

1. **MCP 的作用：** 你运行一个 MCP Server 连接到 SQL Server。现在 AI 拥有了“读写数据库”的能力（它有了手）。
2. **Agent Skills 的作用：** 你加载一个名为 `Sales_Analysis_Pro` 的 Skill。里面规定：分析销售必须包含同比/环比计算、排除异常值、并生成特定格式的报表。
3. **最终执行：** AI 在 Skill 的指导下，通过 MCP 接口发送精准的 SQL 指令。
