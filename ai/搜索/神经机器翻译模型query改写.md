通过结合**神经机器翻译 (NMT)** 与 **强化学习 (RL)** 来增强搜索改写（Search Rewriting），其核心思路是：将搜索改写视为一个翻译过程（将“原始查询”翻译为“高性能查询”），并利用搜索结果的反馈作为奖励信号，解决传统监督学习中“生成文本虽通顺但搜索效果差”的痛点。



## 1. 算法原理：两阶段优化框架

该方案通常采用 **“先监督预训练，后强化微调”** 的架构。

## 第一阶段：NMT 基础模型 (监督学习)

使用 Transformer 编码器-解码器结构。模型学习将用户输入的 Query ($q$) 映射到目标改写 Query ($q^*$)。

- **编码器**：捕捉原始 Query 的语义表示。接收原始搜索词 $q$（例如：“电脑登录不了，没法办公了”），将其转化为高维语义向量。
- **解码器**：生成改写后的候选 Query。基于 Encoder 的输出，逐词预测（Sampling）生成改写后的查询 $q'$（例如：“办公电脑密码到期”）。在 RL 阶段，它是我们的 Policy $\pi_{\theta}$。

## 第二阶段：RL 性能增强 (策略梯度)

NMT 模型作为策略网络（Policy Network）。由于搜索指标（如 CTR、nDCG）不可导，无法通过反向传播直接优化，因此引入强化学习：

1. **动作 (Action)**：模型生成的改写序列 $q'$。
2. **状态 (State)**：原始查询 $q$ 及已生成的词。
3. **奖励 (Reward)**：将 $q'$ 投入搜索引擎，根据返回结果的质量（如点击率、相关性得分）计算奖励值。

## 3. 损失函数选择与计算

模型优化目标是结合“翻译准确性”与“搜索效果”。

## 3.1 监督学习损失 ($L_{MLE}$)

在预训练阶段，使用交叉熵损失（Cross-Entropy）：

$L_{MLE}(\theta) = -\sum_{t=1}^{T} \log P(y_t | y_{<t}, x; \theta)$

其中 $x$ 是原查询，$y$ 是目标改写。

## 3.2 强化学习损失 ($L_{RL}$)

采用策略梯度算法（如 REINFORCE）。我们的目标是最大化期望奖励：

$J(\theta) = \mathbb{E}\_{q' \sim P_{\theta}(\cdot|q)} [R(q', q)]$

对应的梯度计算为：

$\nabla_{\theta} J(theta) \approx \sum_{t=1}^{T} (R(q', q) - B) \nabla\_{\theta} \log P(q'_t | q'_{<t}, q; \theta)$

- $R(q', q)$：奖励函数（例如搜索结果的 MRR 或 nDCG）。
- $B$：基准值（Baseline），用于降低方差，通常使用当前状态的平均奖励。

## 3.3 联合损失

为了防止模型在 RL 阶段产生“病态”查询（虽然搜索得分高但人看不懂），通常保留部分 MLE 约束：

$L_{total} = \alpha L_{RL} + (1-\alpha) L_{MLE}$

## 4. 奖励函数 (Reward) 的设计

这是 RL 成功的关键。常见的奖励来源包括：

- **相关性得分**：改写前后文本的语义相似度（如 Cosine Similarity）。
- **搜索指标**：

  - **点击增益**：如果改写后的点击率 (CTR) 高于原查询，则给予正向奖励。
  - **MRR (Mean Reciprocal Rank)**：目标结果在搜索列表中排位的提升情况。

- **多样性奖励**：鼓励生成与原词不同但含义相关的词。

## 5. 测试指标

评估搜索改写效果需要从“文本质量”和“搜索性能”两个维度进行。

## 离线文本指标

- **BLEU / METEOR**：评估改写结果与标准人工改写的相似度。
- **PPL (Perplexity)**：评估生成句子的语言流畅度。

## 在线/搜索性能指标 (核心)

- **Query Reformulation Rate**：用户手动修改查询的比例（越低代表自动改写越成功）。
- **nDCG (normalized Discounted Cumulative Gain)**：衡量搜索结果的相关性排名。
- **Recall@K**：衡量改写后是否召回了更多相关的文档。
- **Zero-result Rate**：衡量改写是否有效解决了“零结果”问题。
