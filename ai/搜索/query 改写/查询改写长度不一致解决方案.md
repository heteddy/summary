# 查询改写中的长度不一致问题解决方案

## 问题描述

在基于序列标注的查询改写任务中，**源查询和目标查询长度不一致**是一个核心挑战：

```
示例 1（替换）:
源： "电脑登录不了"     (6 tokens)
目标："电脑无法登录"     (5 tokens)

示例 2（插入）:
源： "vpn 到期"        (2 tokens)  
目标："vpn 续费申请"    (4 tokens)

示例 3（删除 + 插入）:
源： "寿改"           (2 tokens)
目标："寿险改革"       (4 tokens)
```

传统的序列标注要求输入输出长度一致，因此需要特殊处理。

---

## 解决方案总览

| 方案                  | 优点            | 缺点              | 适用场景     |
| ------------------- | ------------- | --------------- | -------- |
| **方案 1: 编辑操作标签法**   | 理论完备、支持任意长度变化 | 标签空间大、训练复杂      | 长度变化大的场景 |
| **方案 2: 对齐 + 插入标记** | 实现简单、直观易懂     | 需要扩展词表、改变输入结构   | 中等长度变化   |
| **方案 3: Span 级别改写** | 灵活、可处理复杂改写    | 需要额外的 span 检测模块 | 短语级别的改写  |
| **方案 4: 保持原长（基线）**  | 最简单、无需修改      | 无法处理插入操作        | 长度变化小的场景 |

---

## 方案 1: 编辑操作标签法 ⭐⭐⭐⭐⭐

### 核心思想

将每个位置的任务从"**预测目标词**"改为"**预测编辑操作**"。

### 标签体系设计

```python
标签空间 = {
    0: "KEEP",           # 保持原词不变
    1: "DELETE",         # 删除该位置的词
    2~vocab_size+1: "REPLACE_i"  # 替换为词表中第 i 个词
}
```

### 工作原理

```python
# 示例： "电脑登录不了" → "电脑无法登录"

原始序列：["电", "脑", "登", "录", "不", "了"]
对齐关系： [("电","电"), ("脑","脑"), ("登","无"), ("录","法"), ("不", DELETE), ("了", DELETE)]

标签序列：[KEEP, KEEP, REPLACE_无，REPLACE_法，DELETE, DELETE]
数值化：  [0,    0,    2+vocab_id("无"), 2+vocab_id("法"), 1, 1]
```

### 代码实现

```python
def build_sample_edit_operation(self, original_query, target_query):
    # 1. 分词
    orig_tokens = tokenizer.tokenize(original_query)
    tgt_tokens = tokenizer.tokenize(target_query)

    # 2. 序列对齐
    _, _, operations = align_sequences_advanced(orig_tokens, tgt_tokens)

    # 3. 构建编辑操作标签
    labels = []
    for op_type, src_idx, tgt_idx in operations:
        if op_type == 'KEEP':
            label = 0
        elif op_type == 'DELETE':
            label = 1
        elif op_type == 'REPLACE':
            tgt_token_id = tokenizer.convert_tokens_to_ids([tgt_tokens[tgt_idx]])[0]
            label = tgt_token_id + 2  # 从 2 开始

        labels.append(label)

    return {"input_ids": ..., "labels": labels}
```

### 模型修改

```python
class MacBERTForQueryRewrite(nn.Module):
    def __init__(self, model_name):
        super().__init__()
        self.bert = BertModel.from_pretrained(model_name)

        # 分类头：预测编辑操作（而不是词表）
        # 输出维度 = vocab_size + 2 (KEEP + DELETE)
        self.num_labels = self.bert.config.vocab_size + 2
        self.classifier = nn.Linear(
            self.bert.config.hidden_size, 
            self.num_labels
        )

    def forward(self, input_ids, attention_mask, labels=None):
        outputs = self.bert(input_ids=input_ids, attention_mask=attention_mask)
        sequence_output = outputs.last_hidden_state

        # 预测每个位置的编辑操作
        logits = self.classifier(sequence_output)  # [batch, seq_len, num_labels]

        # 计算损失
        if labels is not None:
            loss_fct = nn.CrossEntropyLoss(ignore_index=-100)
            loss = loss_fct(logits.view(-1, self.num_labels), labels.view(-1))

        return loss, logits
```

### 推理过程

```python
def predict_with_edit_ops(query, model, tokenizer):
    # 1. 获取输入
    tokens = tokenizer.tokenize(query)
    input_ids = tokenizer.convert_tokens_to_ids(tokens)

    # 2. 模型预测
    with torch.no_grad():
        _, logits = model.predict(input_ids)
        predicted_ops = torch.argmax(logits, dim=-1)[0]

    # 3. 应用编辑操作
    result_tokens = []
    for i, op_id in enumerate(predicted_ops):
        if op_id == 0:  # KEEP
            result_tokens.append(tokens[i])
        elif op_id == 1:  # DELETE
            continue  # 跳过该 token
        else:  # REPLACE
            token_id = op_id - 2
            new_token = tokenizer.convert_ids_to_tokens([token_id])[0]
            result_tokens.append(new_token)

    return tokenizer.convert_tokens_to_string(result_tokens)
```

### 优缺点分析

**优点:**

- ✅ 理论上可以处理任意长度的变化
- ✅ 标签语义明确，易于理解
- ✅ 不需要修改输入序列结构

**缺点:**

- ❌ 标签空间巨大（词表大小 + 2）
- ❌ 类别不平衡严重（大部分是 KEEP）
- ❌ 无法直接处理插入操作（需要额外机制）

## 方案 2: 对齐 + 插入标记 ⭐⭐⭐⭐

### 核心思想

在源序列中**显式添加 `<INS>` 标记**来表示需要插入的位置，将长度不一致的问题转化为**等长序列的预测问题**。

### 工作流程

```python
# 示例： "vpn 到期" → "vpn 续费申请"

步骤 1: 序列对齐
源： ["vpn", "到期"]
目标：["vpn", "续", "费", "申请"]

步骤 2: 使用编辑距离算法建立对齐
对齐结果：[("vpn","vpn"), ("<INS>","续"), ("<INS>","费"), ("到期","申请")]

步骤 3: 构建新的输入序列
新输入：["vpn", "<INS>", "<INS>", "到期"]
新目标：["vpn", "续", "费", "申请"]

步骤 4: 正常训练（现在长度一致了！）
```

### 代码实现

```python
def align_sequences_advanced(source_tokens, target_tokens):
    """
    高级序列比对 - 支持插入、删除、替换
    """
    matcher = SequenceMatcher(None, source_tokens, target_tokens)
    aligned_source = []
    aligned_target = []

    for tag, i1, i2, j1, j2 in matcher.get_opcodes():
        if tag == 'equal':
            for k in range(i2 - i1):
                aligned_source.append(source_tokens[i1 + k])
                aligned_target.append(target_tokens[j1 + k])

        elif tag == 'replace':
            src_len = i2 - i1
            tgt_len = j2 - j1
            min_len = min(src_len, tgt_len)

            # 逐位置替换
            for k in range(min_len):
                aligned_source.append(source_tokens[i1 + k])
                aligned_target.append(target_tokens[j1 + k])

            # 处理长度不匹配
            if src_len > tgt_len:
                # 源序列更长 - 多余部分标记为删除
                for k in range(min_len, src_len):
                    aligned_source.append(source_tokens[i1 + k])
                    aligned_target.append("<DEL>")
            elif tgt_len > src_len:
                # 目标序列更长 - 需要插入
                for k in range(min_len, tgt_len):
                    aligned_source.append("<INS>")
                    aligned_target.append(target_tokens[j1 + k])

        elif tag == 'delete':
            for k in range(i2 - i1):
                aligned_source.append(source_tokens[i1 + k])
                aligned_target.append("<DEL>")

        elif tag == 'insert':
            for k in range(j2 - j1):
                aligned_source.append("<INS>")
                aligned_target.append(target_tokens[j1 + k])

    return aligned_source, aligned_target
```

### 训练数据构建

```python
def build_sample_align_with_insert(self, original_query, target_query):
    # 1. 分词
    orig_tokens = self.tokenizer.tokenize(original_query)
    tgt_tokens = self.tokenizer.tokenize(target_query)

    # 2. 高级对齐（自动添加<INS>标记）
    aligned_source, aligned_target, _ = align_sequences_advanced(
        orig_tokens, tgt_tokens
    )

    # 3. 转换为 IDs
    input_ids = [CLS] + tokenizer.convert_tokens_to_ids(aligned_source) + [SEP]

    # 4. 构建 labels
    labels = [-100]  # CLS
    for token in aligned_target:
        if token == "<DEL>":
            labels.append(-100)  # 删除的 token 不参与 loss
        else:
            token_id = tokenizer.convert_tokens_to_ids([token])[0]
            labels.append(token_id)
    labels.append(-100)  # SEP

    return {"input_ids": input_ids, "labels": labels}
```


### 推理过程

```python
def predict_with_insert(query, model, tokenizer):
    # 1. 初始分词
    tokens = tokenizer.tokenize(query)

    # 2. 迭代预测（处理插入）
    max_iterations = 5  # 防止无限插入
    for _ in range(max_iterations):
        # 准备输入
        input_ids = [tokenizer.cls_token_id] + \
                   tokenizer.convert_tokens_to_ids(tokens) + \
                   [tokenizer.sep_token_id]

        # 模型预测
        with torch.no_grad():
            _, logits = model.predict([input_ids])
            predicted_ids = torch.argmax(logits, dim=-1)[0]

        # 解码
        predicted_tokens = tokenizer.convert_ids_to_tokens(predicted_ids)

        # 移除特殊 token
        final_tokens = []
        has_insert = False

        for i, token in enumerate(predicted_tokens):
            if token in [tokenizer.cls_token, tokenizer.sep_token, 
                        tokenizer.pad_token]:
                continue
            elif token == "<INS>":
                # 检测到插入标记 - 需要在该位置插入新词
                # 这里可以使用一个单独的分类器来预测插入什么词
                has_insert = True
                final_tokens.append("[NEED_INSERT]")
            else:
                final_tokens.append(token)

        tokens = final_tokens

        # 如果没有插入标记，结束迭代
        if not has_insert:
            break

    return tokenizer.convert_tokens_to_string(tokens)
```

### 优缺点分析

**优点:**

- ✅ 直观易懂，符合人类直觉
- ✅ 模型架构无需修改
- ✅ 可以同时处理插入和删除

**缺点:**

- ❌ 需要扩展词表（添加 `<INS>`, `<DEL>` 等特殊标记）
- ❌ 推理过程复杂，可能需要多轮迭代
- ❌ 输入序列长度可能显著增加

## 方案 3: Span 级别改写 ⭐⭐⭐

### 核心思想

不在单个 token 级别操作，而是识别**需要改写的片段（span）**，然后对每个 span 进行整体改写。

### 数据格式

```json
{
  "original": "电脑登录不了没法办公了",
  "target": "电脑无法登录无法办公",
  "spans": [
    {
      "start": 2,
      "end": 4,
      "original_text": "登录",
      "rewrite_text": "无法登录"
    },
    {
      "start": 4,
      "end": 6,
      "original_text": "不了",
      "rewrite_text": ""
    },
    {
      "start": 6,
      "end": 8,
      "original_text": "没法",

}
```

## 方案 4: 保持原长（基线方法）⭐⭐

### 核心思想

**强制输入输出长度一致**，对于无法对齐的位置，采用以下策略之一：

1. **复制原词**: 如果目标位置没有对应词，保持原词
2. **忽略**: 将 label 设为 -100，不参与 loss 计算
3. **最近邻**: 使用最近的目标词

### 代码实现

```python
def build_sample_keep_original(self, original_query, target_query):
    orig_tokens = tokenizer.tokenize(original_query)
    tgt_tokens = tokenizer.tokenize(target_query)

    # 强制截断到相同长度
    min_len = min(len(orig_tokens), len(tgt_tokens))
    orig_tokens = orig_tokens[:min_len]
    tgt_tokens = tgt_tokens[:min_len]

    # 正常构建 labels
    input_ids = [CLS] + tokenizer.convert_tokens_to_ids(orig_tokens) + [SEP]
    labels = [-100] + tokenizer.convert_tokens_to_ids(tgt_tokens) + [-100]

    return {"input_ids": input_ids, "labels": labels}
```

### 优缺点分析

**优点:**

- ✅ 实现最简单
- ✅ 无需修改模型

**缺点:**

- ❌ 无法处理插入操作
- ❌ 会丢失信息
- ❌ 性能受限

## 总结

处理长度不一致问题的**最佳实践**：

1. **首选方案**: 对齐 + 插入标记（平衡性能和复杂度）
2. **追求性能**: 编辑操作标签法（理论完备）
3. **复杂场景**: Span 级别改写（灵活性最高）
4. **快速验证**: 保持原长基线（最简单）

**关键洞察**:

- 没有银弹，需要根据具体场景选择
- 建议在您的数据集上进行消融实验
- 可以考虑混合策略，兼顾效率和效果
